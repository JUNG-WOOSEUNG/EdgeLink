### 리뷰에서 고친 주요 버그

- 끊긴 뒤 예약된 자동 재연결이 "연결 끊기"·"페어링 초기화" 뒤에도 남아 지운 기기에 다시 붙던 문제
- 블루투스 전송이 막히면 메인 스레드가 끊기 처리에서 멈출 수 있던 문제 (기다림에 0.2초 제한)
- 단축키 겹침 창에서 기록한 조합을 저장할 방법이 없던 문제 ("그래도 쓰기")
- 단축키 기록 중 다른 앱으로 가면 전환 단축키가 계속 무시되던 문제
- 보정 결과에 이전 값과 새 값이 같게 나오던 문제, 보정값을 범위(0.6~4.0) 밖으로 저장할 수 있던 문제
- 기본 기기가 아닌 아이폰이 계속 재시도하면 확인 창이 계속 떠서 포커스를 뺏던 문제 (5분 동안 다시 묻지 않음)
- 아이폰 조작 중에 뜬 확인 창을 누를 수 없던 문제 (먼저 Mac으로 돌아옴)
- 클립보드 확인 뒤 내용이 바뀌면 확인하지 않은 내용이 가던 문제
- 잠자기 시 끊기·깨어나면 2초 뒤 재연결, 메뉴바에 기기 이름 표시가 동작하지 않던 문제
- 시스템 로그에 블루투스 주소가 그대로 남던 문제 (뒷자리 가림)

마지막으로 수정분만 다시 리뷰(회귀 확인)해서 5건을 더 고쳤어요: 끊을 때 큐에 남은 쓰기가 닫히는 채널로 가던 문제, 직접 끊어둔 상태인데 깨어나면 다시 연결하던 문제, 보정 중 화면 잠금을 "취소"로 표시하던 문제 등.

앱은 `build/EdgeLink.app`에 최신으로 빌드해 두었고, **일부러 실행해 두지 않았어요.** 실행해 두면 밤새 아이폰에 키보드로 연결돼 있어서 아이폰 화면 키보드가 안 나올 수 있어서예요. 아침에 `open build/EdgeLink.app`으로 켜면 돼요.

### 1단계 · 연결 검증

관문 "아이폰에서 커서와 글자가 보인다"를 통과했어요. 가장 큰 위험이던 "macOS가 Mac의 블루투스 HID 흉내를 막는 경우"는 일어나지 않았어요.

| 항목 | 결과 |
| --- | --- |
| 환경 | macOS 26.5 (Apple 실리콘), iPhone 16 Pro, Xcode 없이 Command Line Tools |
| SDP 레코드 등록, PSM 0x11·0x13 수신 등록 | 오류 없음 |
| Mac → 아이폰 연결 (`bthid connect`) | 성공. 새로 연결하면 2.5초 |
| 커서 이동, 글자 입력 | 성공 |
| 쓰기 시간 (Mac 쪽) | 평균 0.03ms, p95 0.06ms, 최대 0.09ms, 188회 실패 0 |
| 전용 큐에서 `writeSync` | 문제 없음 |

알게 된 것:

- **남아 있는 기본 연결 위에서는 제어 채널이 열리지 않았어요.** 첫 시도는 40초, 세 번째는 120초 동안 응답이 없었어요. 기본 연결부터 새로 맺으면 바로 열려서, 남은 연결은 끊고 새로 맺고 채널이 30초 안에 안 열리면 처음부터 한 번 다시 하게 했어요.
- **아이폰 입력기가 한국어면 글자가 한글로 들어가요.** 블루투스 키보드는 키 위치만 보내기 때문이에요. 설계대로 클립보드 보내기는 첫 사용 때 영어로 바꾸라고 안내해요.
- 최근 macOS는 아이폰의 기기 종류(Class of Device)를 0으로 알려줘요. 기기 목록은 이름도 같이 보고 걸러요.
- Command Line Tools만 있으면 Swift Testing 경로를 직접 넘겨야 해요 (`scripts/test.sh`).

아직 안 한 것 (다음 단계를 막지 않음):

- 손쉬운 사용 권한만으로 키 입력을 가로챌 수 있는지 (`bthid tap`)
- AssistiveTouch 장치 목록에 Mac이 보이는 이름
- 240fps 영상으로 잰 실제 지연, CPU 사용량

### 2단계 · 권한과 온보딩

메뉴바 앱(`scripts/build-app.sh` → `build/EdgeLink.app`), 권한 3가지 감시, 8단계 온보딩, 메뉴바 팝오버를 만들었어요.

코드 리뷰(별도 에이전트)에서 나온 것 중 고친 것:

- 1단계 Core: 사용자가 끊었는데 재연결이 걸림, 끊기 처리가 두 번 돎, 오른쪽 ⇧을 떼면 왼쪽 ⇧까지 풀림, SET_REPORT 종류를 안 봄, Ctrl-C로 끝내면 통계가 안 나옴.
- 2단계 앱 14건: 온보딩 창을 닫아도 커서 원 그리기·기기 검색이 계속됨, 페어링 직후 맺어진 연결을 끊고 다시 연결함, 온보딩 뒤 새 기기를 거절함, "온보딩 다시 보기"가 완료 화면으로 열림, 권한 허용 후 다음 단계까지 최대 1.6초(기준 1초), 블루투스를 껐다 켜도 다시 시작하지 않음, 경고 점이 일부 상황에서 안 뜸 등.

직접 써보면서 나온 문제와 해결:

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 손쉬운 사용을 켜도 계속 "설정 열기" | 임시 서명으로 실행했을 때 등록된 권한 기록이 남아 서명이 맞지 않음 | `tccutil reset`으로 EdgeLink 기록 초기화 후 다시 허용 |
| 버튼·메뉴바를 누른 뒤 반응이 느림 | 화면을 그릴 때마다 블루투스 정보(8ms)·모니터 목록을 여러 번 다시 읽음, 화면 전체를 두 번씩 다시 그림 | 한 번만 계산해서 재사용, 중복 알림 제거. 다시 재보니 25초 중 99.7% 대기 |
| 온보딩 창 아래 빈 띠 | 화면 높이 560 고정 + SwiftUI가 제목 표시줄 32pt를 더해 창이 592 | 화면은 창 높이를 채우고 창만 720×560 고정 (직접 재서 확인) |
| 박스가 바닥까지 늘어나고 여백이 모자람 | 카드 높이 맞추기 설정이 모든 카드에 적용됨 | 높이 맞춤이 필요한 곳에만 적용, 바닥 줄과 최소 24pt |
| 키보드 시험이 될 때도 안 될 때도 있음 | 커서가 계속 원을 그리는 중에 입력 | 입력할 땐 원 그리기를 멈춤 |
| 커서 원이 아이폰 왼쪽 위에서 돎 | Mac은 아이폰 커서 위치를 모름 | 왼쪽 위로 밀어 (0, 0)에 맞춘 뒤 화면 크기 × 보정값으로 가운데로 옮기고 원 그리기 |
| "화면 크기 iPhone" 문구가 부자연스러움 | 이미 아는 값을 다시 물음 | 기기 이름으로 알면 숨기고 "아이폰 방향"만 남김 |

화면 확인 방법: 화면 녹화 권한 없이 `EDGELINK_SNAPSHOT=<폴더>`로 모든 화면을 PNG로 그려서 디자인 캔버스와 비교했어요. `EDGELINK_SHOW_ONBOARDING=<단계 번호>`로 원하는 온보딩 단계를 바로 열 수 있어요.
