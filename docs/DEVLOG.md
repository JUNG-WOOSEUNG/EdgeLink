## 2026-10-20 (블루투스 도우미 분리, v0.3.1용)

- **문제**: 아이폰 블루투스를 껐다 켠 뒤 재연결이 실패하는 동안 IOBluetooth가 메인 큐로 보낸 콜백(`callConnectionCompleteCallback → openL2CAPChannelSync → waitforChanneOpen`)에서 채널 열기를 동기로 기다려, 메뉴바가 4~5초마다 3~10초씩 멈췄다. 연결 시도를 전용 스레드로 옮겨도 콜백은 메인으로 와서 앱 코드로는 막을 수 없었다.
- **결정**: 블루투스 HID(SDP·연결 받기·L2CAP 채널·리포트 쓰기)를 도우미 프로세스 `edgelink-hid`로 뺐다. 앱은 `Process`로 띄우고 stdin/stdout 파이프로 짧은 바이너리 메시지를 주고받는다(길이 4바이트 + 종류 1바이트 + 내용, 마우스 움직임 1개 13바이트). XPC는 Xcode 없이 번들 안 XPC 서비스를 만들기 번거롭고, 이 정도 메시지엔 파이프로 충분했다.
  - 도우미: `BluetoothHID`를 그대로 쓴다. 리포트는 명령 읽기 스레드에서 바로 쓰기 큐로 넘겨서 도우미 메인이 IOBluetooth에 붙잡혀도 나간다. 연결·설정은 메인에서. 1초마다 메인에서 하트비트. stdin이 닫히거나 부모가 바뀌면 끊고 끝난다.
  - 앱: `HIDHelperClient`가 `BluetoothHID`와 같은 모양이라 AppModel·InputRouter는 거의 그대로(`writeStatistics` → `flushWrites`). 보내기는 아무 스레드에서 논블로킹(파이프가 차면 남은 바이트를 모아 이어 쓰고, 32KB를 넘으면 버리고 Mac으로 돌아오게 알림, `F_SETNOSIGPIPE`로 도우미가 죽어도 앱은 안 죽음).
  - 연결 받기 허용(기본 기기만/페어링 중엔 모두)은 도우미가 그 자리에서 정해야 해서 규칙을 미리 넘긴다. 거절하면 앱에 알려 확인 창을 띄운다.
  - 감시: 도우미가 끝나면 → 연결 중이었으면 `.helperLost`로 끊김 처리(Mac으로 돌아옴) → 0.5·2·5·15·30초 간격으로 다시 띄우고(1분 넘게 잘 돌면 처음부터) 설정을 다시 보낸 뒤 기본 기기에 다시 연결. 하트비트가 5초 끊기면 연결 중일 때 Mac으로 돌아오고, 20초 끊기면 죽이고 다시 띄운다(실기기 멈춤이 3~10초라 넉넉히).
  - 한 번 연결됐던 기기가 채널을 계속 거절할 때(`hidNeedsFreshProcess`) 앱 전체 대신 도우미만 새로 띄운다(30초에 한 번까지).
  - 로그: 도우미는 줄마다 앱으로 보내고 앱이 같은 `EdgeLink.log`·연결 로그 창에 남긴다(주소 뒷자리 가림은 그대로). HangWatch는 앱에 그대로 둬서 분리 뒤 메인 멈춤이 사라졌는지 확인하는 근거로 쓴다.
  - 번들: `Contents/MacOS/edgelink-hid`. `build-app.sh`가 도우미를 먼저 같은 인증서로 서명(`com.edgelink.EdgeLink.hid`, 블루투스 권한 문구는 `__info_plist`)하고 앱을 서명한다. 업데이트는 번들째 바꾸므로 도우미도 같이 바뀐다.
- **확인**: `swift build` 경고 없음, 테스트 124개 통과(메시지 왕복, 가짜 도우미로 종료·무응답·거절 재시작·재연결·간격 제한, 실제 도우미를 띄워 ping·flush·진단 → `kill -9` → 다시 뜬 도우미 ping → 종료, stdin만 닫아도 도우미가 끝남). 5번 반복해도 통과, 남는 도우미 없음. 업데이트와 같은 플래그(`kSecCSCheckNestedCode` 포함)로 새 번들은 통과, 도우미 바이트를 바꾼 번들은 -67010으로 거절. 캡처 모드(`EDGELINK_SNAPSHOT`)는 49장, 도우미는 뜨지 않음.
- **실기기로만 확인할 것**: [DEVICE-CHECK.md](DEVICE-CHECK.md) "7. 블루투스 도우미". 특히 블루투스 권한이 앱 것으로 묶이는지(자식 프로세스는 보통 앱을 책임 프로세스로 따른다), 입력 지연.
- **남은 위험**: 페어링(`Pairer`)과 기기 찾기는 아직 앱 프로세스에서 IOBluetooth를 쓴다(온보딩·기기 추가 때만). 앱 메인 멈춤이 남아 있으면 HangWatch 로그로 확인한다.

## 2026-10-20 (배포·업데이트)

- **DMG 배포**: `scripts/make-dmg.sh`가 끌어서 설치하는 DMG(배경 그림, 앱 → Applications 화살표, 볼륨 아이콘)를 만든다. 처음엔 Finder AppleScript로 창 모양을 정하려 했는데 Finder 제어가 시간 초과(-1712)로 막혀서, Finder 없이 창 설정 파일을 쓰는 `dmgbuild`(build/.venv에 자동 설치)로 바꿨다.
- **앱 아이콘**: 디자인 캔버스 SVG → `Resources/AppIcon.icns`, 번들에 넣고 설정 › 정보에도 표시.
- **자동 업데이트**: GitHub 릴리스 API(`EdgeLinkUpdateFeed`)를 하루 한 번 확인 → 새 버전이면 확인 창 → DMG 받기 → 새 앱이 지금 앱과 같은 인증서로 서명됐는지 확인(지정 요구사항) → 앱이 끝나면 바꿔 끼우고 다시 켬. 바꾸다 실패하면 예전 앱을 되돌린다. Sparkle은 Xcode 없이 붙이기 번거롭고 서명 키를 따로 관리해야 해서 쓰지 않았다.
  - 시험: 로컬 가짜 릴리스(`EDGELINK_UPDATE_FEED=file://…`, `EDGELINK_UPDATE_AUTOINSTALL=1`)로 0.2.0 → 0.2.1 설치·재실행 확인(3초). 임시 서명한 0.2.2는 "서명이 달라서 설치하지 않았어요"로 거절, 앱은 0.2.1 그대로.
  - 남은 문제: 저장소가 비공개라 로그인 없는 앱은 릴리스를 못 읽는다(404). 저장소를 공개하거나 릴리스만 올리는 공개 저장소가 필요하다.
- **릴리스**: `scripts/release.sh <버전> "<요약>"` — 버전 올림, 테스트, DMG, 태그, `gh release create`.
- **블루투스 껐다 켠 뒤 재연결**: 재시작 없이 4분 지켜봤지만 저절로 붙지 않았다. 앱 재시작(22:20) 뒤에도 실패 → "시간이 지나면 된다", "재시작하면 된다" 둘 다 아님. 실패 뒤 대기 중에도 4초마다 메인 스레드가 3~5초 멈춤(IOBluetooth가 `callConnectionCompleteCallback → openL2CAPChannelSync`로 기다림) → 아이폰 쪽에서 들어오는 연결 시도로 보임. 계속 조사.

### 리뷰에서 고친 주요 버그

- 끊긴 뒤 예약된 자동 재연결이 "연결 끊기"·"페어링 초기화" 뒤에도 남아 지운 기기에 다시 붙던 문제
- 블루투스 전송이 막히면 메인 스레드가 끊기 처리에서 멈출 수 있던 문제 (기다림에 0.2초 제한)
- 단축키 겹침 창에서 기록한 조합을 저장할 방법이 없던 문제 ("그래도 쓰기")
- 단축키 기록 중 다른 앱으로 가면 전환 단축키가 계속 무시되던 문제
- 보정 결과에 이전 값과 새 값이 같게 나오던 문제, 보정값을 범위(0.6~4.0) 밖으로 저장할 수 있던 문제
- 기본 기기가 아닌 아이폰이 계속 재시도하면 확인 창이 계속 떠서 포커스를 뺏던 문제 (5분 동안 다시 묻지 않음)
- 아이폰 조작 중에 뜬 확인 창을 누를 수 없던 문제 (먼저 Mac으로 돌아옴)
- 클립보드 확인 뒤 내용이 바뀌면 확인하지 않은 내용이 가던 문제
- 잠자기 시 끊기·깨어나면 2초 뒤 재연결, 메뉴바에 기기 이름 표시가 동작하지 않던 문제
- 시스템 로그에 블루투스 주소가 그대로 남던 문제 (뒷자리 가림)

마지막으로 수정분만 다시 리뷰(회귀 확인)해서 5건을 더 고쳤어요: 끊을 때 큐에 남은 쓰기가 닫히는 채널로 가던 문제, 직접 끊어둔 상태인데 깨어나면 다시 연결하던 문제, 보정 중 화면 잠금을 "취소"로 표시하던 문제 등.

앱은 `build/EdgeLink.app`에 최신으로 빌드해 두었고, **일부러 실행해 두지 않았어요.** 실행해 두면 밤새 아이폰에 키보드로 연결돼 있어서 아이폰 화면 키보드가 안 나올 수 있어서예요. 아침에 `open build/EdgeLink.app`으로 켜면 돼요.

### 정해주실 것

- **설계 문서(claude.ai 원본)에 반영할 것**: 밤사이 정한 것 중 원본 문서와 달라진 게 있어요. 원본은 제가 고치지 않았어요. 확인해주시면 반영할게요.
  - 단축키 겹침 창: 디자인대로 "다른 조합 고르기 / 그래도 쓰기"
  - 페어링 초기화: 배치는 남기고 기기별 모델·방향을 지움 (캔버스대로)
  - 연결 요청 거절 후 같은 기기는 5분 동안 묻지 않고 거절 (새로 정함)
  - 아이폰 조작 중 확인 창이 필요하면 먼저 Mac으로 돌아옴 (새로 정함)
  - 버튼 등록 도우미의 "다시 보내기" 버튼 (디자인에 없지만 아이폰이 신호를 놓쳤을 때 필요해서 둠)

### 1단계 · 연결 검증

관문 "아이폰에서 커서와 글자가 보인다"를 통과했어요. 가장 큰 위험이던 "macOS가 Mac의 블루투스 HID 흉내를 막는 경우"는 일어나지 않았어요.

| 항목 | 결과 |
| --- | --- |
| 환경 | macOS 26.5 (Apple 실리콘), iPhone 16 Pro, Xcode 없이 Command Line Tools |
| SDP 레코드 등록, PSM 0x11·0x13 수신 등록 | 오류 없음 |
| Mac → 아이폰 연결 (`bthid connect`) | 성공. 새로 연결하면 2.5초 |
| 커서 이동, 글자 입력 | 성공 |
| 쓰기 시간 (Mac 쪽) | 평균 0.03ms, p95 0.06ms, 최대 0.09ms, 188회 실패 0 |
| 전용 큐에서 `writeSync` | 문제 없음 |

알게 된 것:

- **남아 있는 기본 연결 위에서는 제어 채널이 열리지 않았어요.** 첫 시도는 40초, 세 번째는 120초 동안 응답이 없었어요. 기본 연결부터 새로 맺으면 바로 열려서, 남은 연결은 끊고 새로 맺고 채널이 30초 안에 안 열리면 처음부터 한 번 다시 하게 했어요.
- **아이폰 입력기가 한국어면 글자가 한글로 들어가요.** 블루투스 키보드는 키 위치만 보내기 때문이에요. 설계대로 클립보드 보내기는 첫 사용 때 영어로 바꾸라고 안내해요.
- 최근 macOS는 아이폰의 기기 종류(Class of Device)를 0으로 알려줘요. 기기 목록은 이름도 같이 보고 걸러요.
- Command Line Tools만 있으면 Swift Testing 경로를 직접 넘겨야 해요 (`scripts/test.sh`).

아직 안 한 것 (다음 단계를 막지 않음):

- 손쉬운 사용 권한만으로 키 입력을 가로챌 수 있는지 (`bthid tap`)
- AssistiveTouch 장치 목록에 Mac이 보이는 이름
- 240fps 영상으로 잰 실제 지연, CPU 사용량

### 2단계 · 권한과 온보딩

메뉴바 앱(`scripts/build-app.sh` → `build/EdgeLink.app`), 권한 3가지 감시, 8단계 온보딩, 메뉴바 팝오버를 만들었어요.

코드 리뷰(별도 에이전트)에서 나온 것 중 고친 것:

- 1단계 Core: 사용자가 끊었는데 재연결이 걸림, 끊기 처리가 두 번 돎, 오른쪽 ⇧을 떼면 왼쪽 ⇧까지 풀림, SET_REPORT 종류를 안 봄, Ctrl-C로 끝내면 통계가 안 나옴.
- 2단계 앱 14건: 온보딩 창을 닫아도 커서 원 그리기·기기 검색이 계속됨, 페어링 직후 맺어진 연결을 끊고 다시 연결함, 온보딩 뒤 새 기기를 거절함, "온보딩 다시 보기"가 완료 화면으로 열림, 권한 허용 후 다음 단계까지 최대 1.6초(기준 1초), 블루투스를 껐다 켜도 다시 시작하지 않음, 경고 점이 일부 상황에서 안 뜸 등.

직접 써보면서 나온 문제와 해결:

| 문제 | 원인 | 해결 |
| --- | --- | --- |
| 손쉬운 사용을 켜도 계속 "설정 열기" | 임시 서명으로 실행했을 때 등록된 권한 기록이 남아 서명이 맞지 않음 | `tccutil reset`으로 EdgeLink 기록 초기화 후 다시 허용 |
| 버튼·메뉴바를 누른 뒤 반응이 느림 | 화면을 그릴 때마다 블루투스 정보(8ms)·모니터 목록을 여러 번 다시 읽음, 화면 전체를 두 번씩 다시 그림 | 한 번만 계산해서 재사용, 중복 알림 제거. 다시 재보니 25초 중 99.7% 대기 |
| 온보딩 창 아래 빈 띠 | 화면 높이 560 고정 + SwiftUI가 제목 표시줄 32pt를 더해 창이 592 | 화면은 창 높이를 채우고 창만 720×560 고정 (직접 재서 확인) |
| 박스가 바닥까지 늘어나고 여백이 모자람 | 카드 높이 맞추기 설정이 모든 카드에 적용됨 | 높이 맞춤이 필요한 곳에만 적용, 바닥 줄과 최소 24pt |
| 키보드 시험이 될 때도 안 될 때도 있음 | 커서가 계속 원을 그리는 중에 입력 | 입력할 땐 원 그리기를 멈춤 |
| 커서 원이 아이폰 왼쪽 위에서 돎 | Mac은 아이폰 커서 위치를 모름 | 왼쪽 위로 밀어 (0, 0)에 맞춘 뒤 화면 크기 × 보정값으로 가운데로 옮기고 원 그리기 |
| "화면 크기 iPhone" 문구가 부자연스러움 | 이미 아는 값을 다시 물음 | 기기 이름으로 알면 숨기고 "아이폰 방향"만 남김 |

화면 확인 방법: 화면 녹화 권한 없이 `EDGELINK_SNAPSHOT=<폴더>`로 모든 화면을 PNG로 그려서 디자인 캔버스와 비교했어요. `EDGELINK_SHOW_ONBOARDING=<단계 번호>`로 원하는 온보딩 단계를 바로 열 수 있어요.
