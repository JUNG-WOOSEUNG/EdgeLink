# 1단계 · 연결 검증

관문: **아이폰에서 커서와 글자가 보인다.** 통과하지 못하면 나머지는 진행하지 않고 연결 방식부터 다시 정해요 (설계 문서 › 위험 요소: ESP32-S3 USB 동글 방식).

## 준비

```sh
swift build
.build/debug/bthid info     # Mac 블루투스 켜짐 확인
.build/debug/bthid list     # 아이폰이 주소와 함께 나오는지
```

아이폰이 목록에 없으면 아이폰에서 설정 › 블루투스를 열어둔 채로:

```sh
.build/debug/bthid scan
.build/debug/bthid pair <아이폰 주소>
```

아이폰 설정 › 손쉬운 사용 › 터치 › AssistiveTouch를 켜두세요. 켜야 커서가 보여요.

## 시험 순서

위에서부터 하나씩 해보고, 되는 첫 방법에서 멈춰요. 각 시도는 `-v`로 자세한 로그를 남겨요.

| 순서 | 명령 | 무엇을 보나 |
| --- | --- | --- |
| A | `bthid connect <주소> -v` | Mac이 먼저 연결. 로그에 "HID 연결 성공" |
| B | `bthid connect <주소> --cod -v` | Mac을 키보드 종류(0x0025C0)로 보이게 한 뒤 연결 |
| C | `bthid serve -v` | 아이폰 설정 › 블루투스에서 Mac을 눌러 연결 |
| D | `bthid serve --cod -v` | C와 같고, 기기 종류만 키보드로 |

연결되면 자동으로:

1. 커서가 사각형으로 한 바퀴 움직여요.
2. 3초 뒤 "hello edgelink"를 입력해요. 그 전에 아이폰 메모 앱의 입력 칸을 눌러두세요.
3. 쓰기 시간 통계(평균 · p95 · 최대)를 출력해요.

`--interactive`를 붙이면 그 뒤로 터미널에 치는 글자가 아이폰으로 가요 (방향키 = 커서, Ctrl-] = 클릭).

## 같이 확인할 것

- **권한 2개로 줄일 수 있나**: `bthid tap`을 실행해서 "가로채기(defaultTap)"가 입력 모니터링 없이 키 이벤트를 받는지 봐요. 받으면 온보딩에서 입력 모니터링을 빼요. 터미널에서 실행하면 권한은 터미널 앱 기준이라, 시스템 설정에서 터미널의 입력 모니터링을 끈 상태로 시험해요.
- **AssistiveTouch 장치 이름**: 아이폰 설정 › 손쉬운 사용 › 터치 › AssistiveTouch › 장치에 Mac이 어떤 이름으로 보이는지 적어요. 버튼 등록 도우미 문구에 써요.
- **입력 지연**: 통계의 쓰기 시간은 Mac 쪽 절반이에요. 끝까지 재려면 240fps로 Mac 키 입력과 아이폰 화면을 같이 찍어요. 목표는 평균 20ms, 최대 50ms.
- **CPU**: 연결을 유지한 채 활성 상태 보기에서 bthid가 대기 0.5%, `--interactive`로 움직이는 중 3%를 넘지 않는지.
- **쓰기 스레드**: 리포트는 전용 직렬 큐에서 `writeSync`로 보내요. IOBluetooth가 메인 스레드 밖 쓰기를 싫어하면 커서가 멈추거나 Ctrl-C에서 안 끝나요. 그러면 메인 스레드 쓰기로 바꿔요.
- **`--cod`가 먹히는지**: `--cod`로 실행 중에 다른 터미널에서 `bthid info`로 기기 종류가 바뀌었는지 봐요. 최근 macOS는 무시할 수 있어요.
- **ISO 키보드**: `§`와 `` ` `` 키가 아이폰에서 서로 바뀌어 나오는지 (ANSI·JIS는 해당 없음).

## 실패했을 때

- `0xE00002C5`(사용 중) 같은 코드로 채널이 안 열리면 macOS가 HID PSM을 이미 쓰고 있다는 뜻일 수 있어요. 로그 전체를 남겨두세요.
- 아이폰이 연결은 했다가 바로 끊으면 SDP 레코드나 디스크립터 문제일 수 있어요. `bthid sdp`로 내용을 확인해요.
- 다른 Mac이 같은 아이폰에 HID로 붙어 있으면 거부돼요. 그 Mac의 블루투스를 끄고 다시 해요.
