# EdgeLink 설계 문서

> 원본: claude.ai "EdgeLink 설계 문서" (2026-10-19, rev 68)에서 옮긴 사본이에요. 원본과 다르면 원본을 따르고, 고칠 땐 원본부터 고친 뒤 이 파일을 다시 만들어요.

## 개요

EdgeLink는 Mac의 키보드·트랙패드로 아이폰과 아이패드를 조작하게 해주는 메뉴바 앱이에요. Mac이 블루투스 키보드·마우스로 동작하기 때문에 아이폰에는 아무것도 설치하지 않아요.

**목표**

- 커서를 화면 끝으로 밀면 아이폰으로 넘어가고, 반대로 밀면 돌아온다.
- 처음 쓰는 사람도 안내만 따라가면 3분 안에 설정을 끝낸다.
- 모니터가 여러 대여도, 아이폰을 어디에 두어도 실제 위치대로 동작한다.

**범위**

| 포함 | 제외 |
|---|---|
| macOS 13 이상 메뉴바 앱 | 아이폰·아이패드용 앱 |
| 블루투스 HID 키보드·마우스 흉내 | 아이폰 화면을 Mac에 띄우기 |
| 키보드, 포인터, 스크롤, 클릭 전달 | 진짜 클립보드 공유, 파일 전송 |
| 영문 클립보드를 타이핑으로 보내기 | 한글 클립보드 보내기 |
| 아이폰, 아이패드, 안드로이드(참고용) | Windows 지원 |

**설계 원칙**

1. 하는 일과 이유를 항상 알려준다. 권한 요청마다 왜 필요한지 한 줄로 쓴다.
2. 꼭 필요한 기능만 둔다. 자주 바꾸는 것은 팝오버, 나머지는 설정 창에 둔다.
3. 실수해도 돌아올 길이 있다. 단축키 ⌃⌥⌘Space는 어떤 상태에서도 Mac으로 돌아온다.
4. 입력이 엉뚱한 곳에 가지 않는다. 확신할 수 없으면 Mac으로 돌아온다.

## 사용자 흐름

첫 실행은 8단계 온보딩 창으로 진행해요. 2~5단계는 필수이고, 끝내야 아이폰으로 넘어갈 수 있어요.

> 그림: 첫 실행 온보딩 · 8단계, 실패 시 4단계로 되돌아감 (원본 문서에서 보기)

| 단계 | 다음으로 넘어가는 조건 | 막혔을 때 |
|---|---|---|
| 1 시작 | 시작하기 클릭 | 없음 |
| 2 Mac 권한 | 블루투스·손쉬운 사용·입력 모니터링 모두 허용 (자동 감지) | 시스템 설정 안내 그림, "목록에 없으면 + 버튼" 안내, 60초가 지나면 회사 Mac 관리자 문의 안내 |
| 3 페어링 | HID 채널 2개가 열림 | 목록에 없을 때 도움말, 실패 코드와 로그 보기, 다른 Mac에 연결됨 안내, 아이패드는 유니버설 컨트롤 겹침 안내 |
| 4 AssistiveTouch | "켰어요" 체크 (아이패드는 건너뜀). 화면 회전 잠금을 함께 권장 | 없음 |
| 5 연결 확인 | "네, 움직여요" | "안 보여요" → 점검 3가지, 다시 움직이기, 4단계로 |
| 6 배치 | 위치 1개 선택 (기본값: 메인 모니터 오른쪽) | Dock·메뉴 막대 겹침 안내 |
| 7 연습 | 넘어가기·돌아오기·단축키 3개 자동 체크, 또는 건너뛰기 | 보정 도우미 연결 |
| 8 완료 | EdgeLink 사용하기, 제스처 설정(선택) 링크 | 없음 |

**이후 실행**

- 온보딩을 끝낸 뒤에는 창 없이 메뉴바에만 떠요. 기본 기기에 자동으로 연결해요.
- 필수 단계 중 하나가 풀리면(권한 꺼짐, 기기 삭제) 팝오버가 해당 단계로 안내해요. 온보딩 창을 다시 열지 않고 필요한 카드만 보여줘요.
- 설정 › 배치의 "온보딩 다시 보기"로 언제든 처음부터 다시 할 수 있어요.
- 저장하는 값: 마지막으로 끝낸 단계 번호(`onboardingStep`), 완료 여부(`onboardingDone`).

## macOS 권한 설계

필수 권한은 블루투스, 손쉬운 사용, 입력 모니터링 3가지예요. 하나라도 없으면 아이폰으로 넘어가지 않고, 팝오버와 설정 창에 무엇이 빠졌는지 보여줘요.

| 권한 | 필요한 이유 (화면 문구) | 확인 방법 | 요청 방법 | 허용 후 |
|---|---|---|---|---|
| 블루투스 | Mac이 아이폰에 키보드·마우스로 보이게 해요 | `CBManager.authorization` | 첫 IOBluetooth 호출 때 시스템 창이 자동으로 뜸. 거부했으면 설정 › 개인정보 보호 › 블루투스 열기 | SDP 레코드 등록부터 다시 시작 |
| 손쉬운 사용 | 아이폰 조작 중엔 입력이 Mac에 가지 않도록 막아요 | `AXIsProcessTrusted()` | `AXIsProcessTrustedWithOptions(prompt: true)` 후 설정 › 손쉬운 사용 열기 | 이벤트 탭 생성 |
| 입력 모니터링 | 키보드 입력을 읽어서 아이폰으로 보내요 | `CGPreflightListenEventAccess()` | `CGRequestListenEventAccess()` 후 설정 › 입력 모니터링 열기 | 이벤트 탭 다시 생성 |
| 로그인 항목 (선택) | Mac을 켜면 바로 연결돼요 | `SMAppService.mainApp.status` | `register()`. 상태가 승인 필요면 설정 › 로그인 항목 열기 | 없음 |

**요청 순서와 타이밍**

1. 블루투스를 먼저 요청해요. 시스템 창이 앱 안에서 바로 떠서 가장 쉽기 때문이에요. 앱은 온보딩 2단계 전까지 블루투스를 쓰지 않아서, 설명 없이 시스템 창이 먼저 뜨는 일이 없어요. 온보딩을 마친 뒤에는 앱을 켤 때 바로 시작해요.
2. 손쉬운 사용과 입력 모니터링은 시스템 설정으로 보내야 해요. 한 번에 하나씩, 앞의 것이 허용되면 다음 버튼이 강조돼요.
3. 시스템 설정이 열려 있는 동안 1초마다 상태를 다시 확인해요. 허용되면 앱을 재시작하지 않고 바로 다음으로 넘어가요.
4. 앱이 다시 앞으로 오면(`didBecomeActive`) 즉시 한 번 더 확인해요.

**설정 화면 안내**

- 시스템 설정이 열리면 온보딩 창에 "목록에서 EdgeLink를 켜주세요" 안내와 그림을 보여줘요.
- 목록에 앱이 없을 때를 위해 "+ 버튼으로 추가하세요" 문구를 같이 써요.
- 입력 내용은 저장하거나 인터넷으로 보내지 않는다는 개인정보 문구를 권한 화면 하단에 항상 둬요.

**권한이 나중에 꺼졌을 때**

- 실행 중에 사용자가 권한을 끄면 이벤트 탭이 멈춰요. 1초마다 확인하다가 꺼진 걸 알면 즉시 Mac 조작으로 돌아오고, 메뉴바 아이콘에 경고 점을 띄워요.
- 팝오버를 열면 연결 화면 대신 "권한이 꺼졌어요" 카드와 다시 켜기 버튼을 보여줘요.

**개발 중 주의**

- 임시 서명은 빌드마다 바뀌어서 권한이 풀려요. 개발용 인증서로 서명해서 피해요.
- 꼬이면 `tccutil reset Accessibility <번들 ID>`, `tccutil reset ListenEvent <번들 ID>`로 초기화해요.

**아이폰 쪽에 필요한 것** (권한은 아니지만 온보딩에서 안내)

- 블루투스 페어링 승인: 두 기기에 같은 번호가 뜨면 아이폰에서 "페어링"을 눌러요.
- AssistiveTouch: 아이폰은 이걸 켜야 커서가 보여요. 아이패드는 필요 없어요.
- EdgeLink는 아이폰의 설정 상태를 알 수 없어요. 그래서 연결 확인 단계에서 사용자에게 직접 물어봐요.

화면은 온보딩 창, 메뉴바 팝오버, 설정 창, 알림, 모서리 효과 5가지예요. 모든 화면은 디자인 캔버스 "EdgeLink 메뉴바 & 설정"에 있어요.

| 화면 | 언제 보이나 | 크기 | 담는 것 |
|---|---|---|---|
| 온보딩 창 | 첫 실행, 또는 필수 단계가 덜 끝났을 때 | 720×560 | 8단계 안내 (사용자 흐름 참고) |
| 팝오버 · 연결됨 | 메뉴바 아이콘 클릭 | 너비 360 | 조작 기기 전환, 배치 미리보기, 스위치 3개(모서리 전환, 유리 효과, 미디어 키를 아이폰으로), 클립보드 보내기, 기기 선택 메뉴(연결된 기기 체크, 다른 기기, 새 기기 페어링, 연결 끊기) |
| 팝오버 · 연결 전 | 기기가 연결되지 않았을 때 | 너비 360 | 두 가지로 나뉨. 온보딩 미완료: 진행 상황(3/8)과 "설정 이어하기" 버튼 하나. 설정 완료 후 끊김: 기본 기기 다시 연결, 다른 기기 목록, 실패 이유 |
| 팝오버 · 문제 있음 | 권한 꺼짐, Mac 블루투스 꺼짐 | 너비 360 | 무엇이 문제인지, 해결 버튼 하나, 나머지 기능은 흐리게 |

| 설정 창 | 팝오버의 설정, ⌘, | 860×640 | 일반 · 배치 · 입력 · 연결 · 정보 탭 |
| 보정 도우미 | 설정 › 배치, 온보딩 연습 단계 | 시트 420 | 안내, 움직인 양, 결과. 같은 형식의 "아이폰 버튼 등록 도우미" 창(720×560)이 설정 › 입력과 온보딩 뒤 선택 단계에 있음 |
| 알림 | 상태가 바뀔 때 | 내용에 맞춤 | 커서가 있는 화면 위쪽에 2.5초 |

**작은 창과 상태** (캔버스 4-4)

| 화면 | 언제 보이나 | 담는 것 |
|---|---|---|
| 클립보드 보내는 중 | 클립보드 보내기를 누른 뒤 | 진행 막대, 남은 글자 수, "Esc로 멈추기". 화면 위쪽 알림 자리에 뜨고 끝나면 "보냈어요"로 바뀜 |
| 연결 로그 보기 | 설정 › 연결 › 연결 로그 보기 | 최근 500줄(시각 · 내용), 오류 줄 강조, 복사(주소 뒷자리 가림), 닫기 |
| 페어링 초기화 확인 | 설정 › 연결 › 페어링 초기화 | 무엇이 지워지는지, Mac과 아이폰에서 해야 할 일, 취소 / 초기화(빨강) |
| 블루투스 권한 거부됨 | 온보딩 2단계에서 시스템 창의 "허용 안 함"을 눌렀을 때 | 거부됐다는 안내, "시스템 설정에서 켜기", 켜면 자동으로 다음 권한으로 넘어감 |

**접근성**

- "동작 줄이기"가 켜져 있으면 유리 효과는 페이드만 하고 크기 애니메이션은 하지 않아요.
- 모든 버튼과 스위치에 VoiceOver 이름을 달아요. 아이콘만 있는 버튼(설정 톱니)도 포함이에요.
- 상태는 색만으로 구분하지 않고 글자를 같이 써요 ("연결됨", "연결 실패").

**공통 규칙**

- 팝오버 높이는 내용에 맞춰요(최대 640). 상태마다 고정 높이를 두지 않아요.
- 누를 수 없는 버튼은 흐리게 하고, 바로 아래에 이유를 한 줄 써요. 예: 보정 도우미 → "아이폰을 연결하면 쓸 수 있어요".
- 이 문서의 표가 수치의 기준이에요. 캔버스 보드(모서리 효과 · 움직임 시안 등)는 이 값을 보여주는 용도라서, 값을 바꿀 땐 문서부터 고쳐요.

|---|---|

| 배치 | 모니터 배치도(드래그), 상태와 충돌 안내, 기기 모델, 세로/가로와 회전 잠금 안내, 포인터 보정, 보정 도우미, 온보딩 다시 보기 |

| 연결 | 기기 목록, 새 기기 페어링, 기본 기기만 연결 허용, 자동 재연결, 잠자기 시 끊기, 연결 로그, 페어링 초기화 |
| 정보 | 버전, 권한 3가지 상태와 바로가기, 자동으로 업데이트 확인, 지금 확인 |

**모서리 효과 수치**

| 상태 | 튀어나온 두께 | 길이 | 불투명도 | 시간 |
|---|---|---|---|---|
| 미는 중 | 4 → 26pt | 70 → 180pt | 25 → 100% | 따라감 |
| 넘어가는 순간 | 34pt | 220pt | 100% | 0.12초 |

- 알약 길이는 통로 길이를 넘지 않아요. 알약 절반은 화면 밖에 있어서 가장자리에 붙어 튀어나온 모양이 돼요.
- 색은 Innovation Blue(#0097E4) 16% 틴트와 흰 테두리 50%예요.

**문구 원칙**: 존댓말 "~해요", 버튼은 2~8자, 이모지 없음. 빨강(#EB1E1E)은 위험한 버튼(페어링 초기화)과 오류에만 써요.

- 글꼴은 SUIT(OFL)를 앱에 넣고, 없으면 Apple SD Gothic Neo를 써요.

## 핵심 동작

입력은 `CGEventTap` 하나로 받고, 모드에 따라 Mac에 그대로 보내거나 막고 블루투스 HID 리포트로 바꿔 아이폰에 보내요.

**블루투스 HID**

- Mac이 HID 콤보 장치(키보드 Report 1 + 마우스 Report 2)의 SDP 레코드를 공개하고, L2CAP 제어 채널 0x11과 인터럽트 채널 0x13을 열어요.
- 키보드 리포트: 수정키 1바이트 + 예약 1 + 키 6개. 마우스 리포트: 버튼 8개(1바이트) + X·Y·휠·가로 스크롤 각 1바이트(−127~127).
- 마우스 움직임은 모아서 8ms(125Hz)마다 보내고, 127을 넘으면 여러 리포트로 나눠요.

**통로(넘어가는 구간)**

- 통로 = 아이폰이 맞닿은 모서리 구간 ∩ 다른 모니터와 맞닿지 않은 구간 − 꼭짓점 24pt(핫 코너).
- 통로 길이가 60pt보다 짧으면 그 자리엔 놓을 수 없어요.
- 저장 값: 모니터 UUID, 모서리, 모서리 시작점에서의 거리. 모니터가 없으면 임시로 다른 빈 모서리를 쓰고 저장 값은 유지해요.

**넘어가기**

1. 커서가 통로에 닿은 채 바깥으로 민 양을 모아요. 통로를 벗어나면 0으로 초기화해요.
2. 민 양이 기준을 넘으면 넘어가요. 기준 = 60 + 감도 × 200pt. Dock·메뉴 막대와 같은 쪽이면 1.8배예요.
3. 넘어가는 순간: Mac 커서를 모니터 가운데로 옮기고 고정·숨김, 아이폰 포인터를 진입 모서리 끝으로 보낸 뒤(5000 단위) 같은 비율 위치로 옮겨요.
4. 비밀번호 입력 중(`IsSecureEventInputEnabled`)이면 넘어가지 않고 알림을 띄워요.

**돌아오기**

- 아이폰 안의 위치를 Mac이 추정해요: 안쪽 거리 0 ~ 화면 깊이 × 보정값, 모서리 방향 0 ~ 화면 길이 × 보정값으로 제한.
- 안쪽 거리가 −90 단위 아래로 내려가고, 그 높이가 통로 안이고, 버튼을 누르고 있지 않으면 돌아와요.
- 돌아온 커서는 같은 비율 높이, 모서리에서 24pt 안쪽에 놓여요.

**보정**

- 보정값 = 아이폰 1pt당 HID 이동량. 기본 2.0, 범위 0.6~4.0.
- 보정 도우미: 포인터를 왼쪽 위로 보낸 뒤 사용자가 오른쪽 아래까지 옮기고 클릭 → (가로 이동 ÷ 화면 너비 + 세로 이동 ÷ 화면 높이) ÷ 2.
- 결과가 0.2보다 작으면 실패로 보고 저장하지 않아요.

**키 매핑**

| Mac 입력 | 아이폰에 보내는 것 |
|---|---|
| 일반 키 | macOS 키코드 → HID Usage 표(ANSI, JIS 英数·かな 포함) |
| ⌃ ⌥ ⇧ ⌘ | HID 왼쪽 수정키. ⌘는 아이폰 ⌘ 단축키로 동작 |
| Caps Lock | 한/영 설정이 켜져 있으면 ⌃Space, 꺼져 있으면 Caps Lock |
| 키 반복 | 보내지 않음 (아이폰이 알아서 반복) |
| 트랙패드 스크롤 | 12pt마다 휠 1칸, 반전 설정 반영 |
| 클립보드 보내기 | 영문·숫자·기호를 12ms 간격으로 타이핑. 그 외 글자는 빼고 알림 |

**추가 규칙**

| 입력 | 규칙 |
|---|---|
| 볼륨·재생·밝기 키 | 설정을 켜면 HID Consumer Control 리포트(Report 3)로 아이폰에 보냄. 기본은 꺼짐(Mac에 둠): Mac에서 음악을 들으며 아이폰을 조작하는 경우가 많아서. 팝오버 스위치로 바로 바꿀 수 있음. 밝기는 항상 Mac |
| 트랙패드 제스처 | 아이폰 조작 중엔 gesture·swipe·magnify·rotate 이벤트를 Mac에 보내지 않고, 아래 "제스처를 아이폰 동작으로" 규칙에 따라 추가 버튼으로 바꿔 보냄 |
| 넘어갈 때 눌린 키 | 넘어가는 순간 눌려 있던 키를 기록하고, 그 키의 뗌 신호는 Mac에 그대로 보냄. 아이폰에는 새로 누른 키만 보냄 |
| 첫 리포트 | 연결·재연결 직후 키보드와 마우스 빈 리포트를 먼저 보내서 아이폰에 눌린 키가 남지 않게 함 |
| Fn·Globe 키 | 아이폰으로 보내지 않음 (받아쓰기·이모지 창이 Mac에서 뜨지 않게 막기만 함) |

**스레드 규칙**

- 이벤트 탭 콜백은 1ms 안에 끝내요. 블루투스 쓰기는 전용 직렬 큐에서 해요.
- 큐가 밀리면 마우스 움직임은 하나로 합치고, 키보드·버튼 리포트는 순서대로 모두 보내요.
- 쓰기 한 번이 50ms를 넘으면 로그에 남기고, 3번 연속이면 Mac으로 복귀해요.

**제스처를 아이폰 동작으로**

블루투스 마우스로는 손가락 제스처를 보낼 수 없어서, 제스처를 마우스 추가 버튼(4~8번) 누름으로 바꿔 보내요. 아이폰 AssistiveTouch가 버튼마다 지정된 동작을 실행해요.

| Mac 제스처 | 대체 단축키 | 보내는 버튼 | 아이폰에서 지정할 동작 (기본 추천) |
|---|---|---|---|
| 세 손가락 위로 쓸기 | ⌃⌥⌘↑ | 버튼 4 | 앱 전환기 |
| 네 손가락 모으기 | ⌃⌥⌘H | 버튼 5 | 홈 |
| 세 손가락 아래로 쓸기 | ⌃⌥⌘↓ | 버튼 6 | 알림 센터 |
| 네 손가락 아래로 쓸기 | ⌃⌥⌘C | 버튼 7 | 제어 센터 |
| 없음 (단축키만) | ⌃⌥⌘L | 버튼 8 | 잠금 화면 |

- 버튼은 누름 리포트 직후 뗌 리포트를 보내요 (클릭 한 번). 제스처 하나에 한 번만 보내요.
- 제스처와 단축키는 각각 켜고 끌 수 있고, 버튼 번호와 단축키는 바꿀 수 있어요.
- macOS가 먼저 가져가는 제스처(Mission Control, Spaces 전환)는 막지 못할 수 있어요. 1단계에서 막히는 제스처를 확인하고, 막히는 건 입력 탭에서 "이 제스처는 Mac이 먼저 써요 · 단축키를 쓰세요"로 안내해요.
- 앱 사이 좌우 넘기기, 뒤로 가기는 AssistiveTouch 동작에 없어서 지원하지 않아요.
- 아이패드는 키보드 단축키가 더 확실해서, 기기가 아이패드면 버튼 대신 ⌘H(홈), ⌘Tab(앱 전환)을 보내는 옵션을 둬요.

**아이폰 버튼 등록 도우미**

1. 설정 › 입력 › "아이폰 버튼 등록"을 열면 아이폰에서 할 일을 순서대로 보여줘요: 설정 › 손쉬운 사용 › 터치 › AssistiveTouch › 장치 › (이 Mac의 블루투스 이름, 예: 지민의 MacBook Pro) › 추가 버튼 사용자화.
2. 아이폰이 "버튼을 누르세요"를 띄우면 Mac에서 "버튼 4 보내기"를 눌러요. 아이폰이 버튼을 인식해요.
3. 아이폰에서 동작(앱 전환기)을 고르면, Mac에서 "등록했어요"를 눌러 다음 버튼으로 넘어가요.
4. 끝나면 "시험해보기"로 제스처를 해서 아이폰에서 동작하는지 확인해요.

온보딩 7단계(연습)가 끝난 뒤 "제스처도 쓰시겠어요?"로 선택 단계로 안내하고, 건너뛰어도 설정에서 언제든 할 수 있어요.

**단축키 기본값**: 전환 ⌃⌥⌘Space, 클립보드 보내기 ⌃⌥⌘V, 모서리 전환 켜기/끄기 ⌃⌥⌘E. 제스처 대체 단축키도 모두 ⌃⌥⌘로 시작해요. ⌃⌥만 쓰면 VoiceOver 조작키, ⌃⌥Space는 macOS 입력 소스 전환과 겹치기 때문이에요. 수정키가 하나 이상 있어야 하고, 겹치면 저장하지 않아요. 사용자가 새 조합을 기록할 때 macOS 시스템 단축키(입력 소스 전환 ⌃Space·⌃⌥Space, Mission Control ⌃↑ 등)와 겹치거나, VoiceOver가 켜져 있는데 ⌃⌥만 쓰는 조합이면 확인 창을 띄워요. 기본값은 겹치지 않아서 온보딩에서는 확인하지 않아요.

## 상태와 예외 처리

아이폰 조작은 연결됨 상태에서만 가능하고, 문제가 생기면 항상 Mac 조작으로 강제 복귀해요. 복귀할 때는 눌린 키와 버튼을 모두 뗀 상태로 아이폰에 보내요.

> 그림: 연결 상태 4개와 조작 모드 3개 (원본 문서에서 보기)

| 분류 | 상황 | 감지 방법 | 동작 | 사용자에게 |
|---|---|---|---|---|
| 입력 안전 | 아이폰 조작 중 Mac 비밀번호 입력 | `IsSecureEventInputEnabled` 0.25초마다 | 강제 복귀 | 알림 "비밀번호 입력이 시작돼서 돌아왔어요" |
| 입력 안전 | 비밀번호 입력 중 넘어가려 함 | 넘어가기 직전 확인 | 넘어가지 않음 | 알림 "넘어갈 수 없어요" |
| 입력 안전 | 기본 기기가 아닌 기기가 연결해 옴 | 수신 채널의 기기 주소 비교 | 채널을 열지 않고 보류 (보안과 개인정보 › 연결 허용 규칙) | 연결 요청 확인 창 (허용 / 거절) |
| 입력 안전 | 이벤트 탭이 시간 초과로 꺼짐 | `tapDisabledByTimeout` | 즉시 다시 켜고, 아이폰 조작 중이었으면 강제 복귀 | 알림 "잠깐 멈춰서 Mac으로 돌아왔어요" |
| 입력 안전 | 블루투스 전송이 막혀 느려짐 | 전송 대기열 길이, 쓰기 시간 50ms 초과 | 전송은 별도 스레드, 대기열 넘치면 움직임만 합치고 키는 유지 | 없음 |
| 입력 안전 | 트랙패드 제스처 (세 손가락 쓸기 등) | gesture·swipe·magnify 이벤트 | Mac에 보내지 않고 추가 버튼으로 바꿔 보냄 (핵심 동작 › 제스처를 아이폰 동작으로) | 없음 |
| 입력 안전 | 볼륨·밝기 등 미디어 키 | system-defined 이벤트 | 설정에 따라 아이폰으로 보내거나 Mac에 둠 (기본: Mac, 핵심 동작 › 추가 규칙) | 없음 |
| 입력 안전 | 화면 잠금, 화면 보호기, 사용자 전환 | `screenIsLocked`, `screensaver.didstart`, `sessionDidResignActive` | 강제 복귀 | 없음 |
| 눌린 키 | 수정키를 누른 채 넘어감 (단축키 포함) | 넘어갈 때 눌린 키 기록 | 그 키를 떼는 신호는 Mac에 그대로 전달 (핵심 동작 › 추가 규칙) | 없음 |
| 눌린 키 | 아이폰에서 키를 누른 채 돌아옴, 연결 끊김 | 복귀·끊김 시점 | 빈 리포트를 보내 모두 뗌. 다시 연결되면 첫 리포트도 빈 리포트 | 없음 |
| 눌린 키 | 버튼을 누른 채 돌아오려 함 | 버튼 상태 | 버튼을 뗄 때까지 복귀 보류 | 없음 |
| 눌린 키 | 아이폰 조작 중 앱 종료·충돌 | SIGTERM·SIGINT 처리, 다음 실행 시 확인 | 커서 고정 해제, 커서 표시, 빈 리포트 | 없음 |
| 연결 | 블루투스 끊김 | L2CAP 채널 닫힘 | 강제 복귀, 재연결 15초 → 1분 → 5분으로 늘림 | 메뉴바 아이콘 빗금 |
| 연결 | Mac 블루투스 꺼짐 | 블루투스 전원 상태 알림 | 재연결 중지 | 팝오버에 "블루투스가 꺼져 있어요" + 켜기 안내 |
| 연결 | 다른 Mac이 같은 아이폰에 연결 중 | 연결 거부 코드 | 재연결 간격 늘림 | "다른 기기에 연결돼 있어요" |
| 연결 | 아이폰이 Virtual Cable Unplug 보냄 | HIDP 제어 메시지 0x15 | 직접 끊은 것으로 처리 | 팝오버에 연결 끊김 |
| 연결 | 사용자가 직접 끊음 | 버튼 동작 | 자동 재연결 중지 | 다시 연결은 사용자가 선택 |
| 연결 | Mac 잠자기 / 깨어남 | `willSleep` / `didWake` | 설정에 따라 끊기 / 2초 뒤 재연결 | 없음 |

## 보안과 개인정보

EdgeLink는 모든 키 입력을 볼 수 있는 앱이라, 입력이 허락한 기기에만 가고 어디에도 남지 않게 하는 것이 최우선이에요.

**연결 허용 규칙**

- 기본은 "기본 기기만 연결 허용"이에요. 기본 기기가 아닌 기기가 연결해 오면 채널을 열지 않고 확인 창을 띄워요.
- 확인 창: 기기 이름, "이 기기로 키보드와 트랙패드 입력을 보내요", 허용 / 거절. 30초 안에 답이 없으면 거절해요.
- 허용하면 그 기기가 새 기본 기기가 돼요. 이전 기본 기기는 목록에 남아요.
- 설정 › 연결에서 이 규칙을 끌 수 있지만, 끄면 경고 문구를 보여줘요. 사용자가 직접 페어링한 기기(온보딩 3단계, "새 기기 페어링", "근처 아이폰 찾기")는 확인 창 없이 바로 기본 기기가 돼요.

**남기지 않는 것**

- 키 입력 내용, 클립보드 내용은 로그·설정·충돌 보고 어디에도 쓰지 않아요. 로그에는 "키보드 리포트 전송" 같은 동작만 남겨요.
- 연결 로그 보기·복사에는 기기 이름과 블루투스 주소가 들어가요. 복사할 때 주소 뒷자리를 가려요.
- 업데이트 확인 외에는 네트워크를 쓰지 않아요. 업데이트 확인도 정해진 HTTPS 주소 한 곳만 써요.

**회사 Mac에서 쓸 때**

- MDM 프로필이 손쉬운 사용·입력 모니터링을 막으면 사용자가 켤 수 없어요. 60초가 지나도 허용되지 않으면 "회사 Mac이라면 관리자에게 문의하세요"를 보여줘요.
- 매체 제어나 DLP 정책이 블루투스 키보드 장치를 막을 수 있어요. 연결 실패 화면에 이 가능성을 함께 안내해요.
- 클립보드 보내기는 Mac의 텍스트를 외부 기기로 옮기는 기능이에요. 회사 배포판에서는 이 기능을 끌 수 있게, 관리 설정(`clipboardTypingAllowed`)으로 막는 옵션을 둬요.
- 사내 배포 전 보안 정책 담당자 검토 항목: 외부 기기로의 입력 전달, 클립보드 타이핑, 비공개 API 사용.

## 성능 · 지원 범위 · 업데이트

입력 지연 20ms 이내가 "쓸 만하다"의 기준이에요. 1단계 연결 검증에서 이 수치부터 재요.

**성능 기준**

| 항목 | 목표 | 재는 방법 |
|---|---|---|
| 입력 지연 (Mac 입력 → 아이폰 반응) | 평균 20ms 이내, 최대 50ms | 이벤트 탭 시각과 블루투스 쓰기 완료 시각 비교 + 화면 녹화(240fps) |
| 넘어가기 반응 | 기준만큼 민 순간부터 효과 시작까지 16ms 이내 | 이벤트 시각과 효과 창 갱신 시각 비교 |
| 이벤트 탭 처리 시간 | 콜백 1회 1ms 이내 | 콜백 앞뒤 시각 기록 |
| CPU (Mac 조작 중, 대기) | 0.5% 이하 | 활성 상태 보기 |
| CPU (아이폰 조작 중) | 3% 이하 | 활성 상태 보기 |
| 메모리 | 60MB 이하 | 활성 상태 보기 |
| 배터리 (Mac) | 대기 중 "에너지 영향" 낮음 | 활성 상태 보기 › 에너지 |
| 재연결 | 깨어난 뒤 5초 안에 연결 | 로그 시각 |

**지원 범위**

| 구분 | 지원 | 비고 |
|---|---|---|
| Mac | macOS 13 Ventura 이상, Apple 실리콘·Intel | 로그인 항목 API(SMAppService) 때문에 13 이상 |
| 아이폰 | iOS 13 이상 | AssistiveTouch 마우스 커서가 iOS 13부터 지원 |
| 아이패드 | iPadOS 13.4 이상 | 기본 마우스 커서가 13.4부터 지원 |
| 안드로이드 | 참고용 (공식 지원 아님) | 열린 질문 참고 |
| 모니터 | 대수 제한 없음 | 미러링 중인 화면은 하나로 봄 |

**업데이트**

- 직접 배포라서 Sparkle 2로 자동 업데이트하고, 파일은 GitHub에 올려요. 업데이트 파일은 EdDSA로 서명해서 가짜 업데이트를 막아요.
- 하루 한 번 확인하고, 새 버전이 있으면 메뉴바 팝오버 바닥에 "새 버전 있음 · 설치"를 한 줄 보여줘요. 아이폰 조작 중에는 알리지 않아요.
- 업데이트 확인 주소는 HTTPS 한 곳만 써요. 이것이 앱이 쓰는 유일한 네트워크라서, 보안과 개인정보의 "네트워크를 쓰지 않아요"를 "업데이트 확인 외에는 네트워크를 쓰지 않아요"로 바꿔요.
- 설정 › 정보에 "자동으로 업데이트 확인" 스위치와 "지금 확인" 버튼을 둬요. 회사 배포판은 관리 설정으로 끌 수 있어요.

**GitHub 배포 구성**

| 무엇 | 어디에 | 주소 예시 |
|---|---|---|
| 업데이트 파일 (.zip, 공증 완료) | GitHub Releases, 버전마다 릴리스 하나 | `github.com/<조직>/edgelink/releases/download/v1.2.0/EdgeLink-1.2.0.zip` |
| 설치 파일 (.dmg) | 같은 릴리스에 함께 | `…/v1.2.0/EdgeLink-1.2.0.dmg` |
| appcast.xml | GitHub Pages (`gh-pages` 브랜치) | `https://<조직>.github.io/edgelink/appcast.xml` |

- 앱의 Info.plist에 `SUFeedURL` = appcast 주소, `SUPublicEDKey` = 공개 키를 넣어요.
- appcast는 릴리스 첨부 파일이 아니라 Pages에 둬요. 주소가 버전마다 바뀌지 않아야 하기 때문이에요.
- 저장소가 비공개면 Releases 파일을 앱이 받을 수 없어요. 배포용 저장소는 공개로 두거나, 코드 저장소와 배포 저장소를 나눠요(코드는 비공개, 배포 파일만 공개).

**릴리스 순서**

1. Developer ID로 서명 → Apple 공증 → staple
2. `.zip`과 `.dmg`를 만들고, Sparkle의 `sign_update`로 `.zip`에 EdDSA 서명
3. GitHub Release(`v1.2.0`)를 만들고 두 파일을 올림
4. `generate_appcast`로 appcast.xml을 갱신해서 `gh-pages`에 올림
5. 테스트용 Mac에서 이전 버전 앱의 "지금 확인"으로 업데이트되는지 확인

GitHub Actions로 2~4를 자동화할 수 있지만, 서명 키를 Actions에 넣어야 해서 처음에는 개발자 Mac에서 직접 해요.

**서명 키 관리** (공급망 공격 대비)

- EdDSA 개인 키는 `generate_keys`로 만들면 Mac 키체인에 저장돼요. 이 키는 저장소, Actions 비밀값, 채팅·메일 어디에도 올리지 않아요.
- 개인 키는 오프라인 백업 1부(암호화된 외장 저장소)만 만들어요. 잃어버리면 기존 사용자에게 업데이트를 보낼 수 없어요.
- 개인 키가 샜다고 의심되면: 새 키를 만들고, 새 공개 키를 넣은 버전을 기존 키로 마지막으로 서명해 배포한 뒤, 기존 키를 폐기해요.
- 저장소는 2단계 인증 필수, `gh-pages`와 릴리스 생성은 보호 규칙으로 관리자만 할 수 있게 해요.
- Sparkle의 사양 정보 전송(`SUEnableSystemProfiling`)은 끈 채로 둬요.

## 개발 순서와 검증 체크리스트

블루투스 연결 확인이 첫 관문이에요. 1단계가 통과하지 못하면 나머지는 진행하지 않고 연결 방식부터 다시 정해요.

**1단계 · 연결 검증** (관문: 아이폰에서 커서와 글자가 보인다)

- `swift build`로 EdgeLinkCore와 bthid가 빌드된다
- `bthid list`에 페어링한 아이폰이 주소와 함께 나온다
- `bthid connect`로 연결되고 로그에 "HID 연결 성공"이 찍힌다
- 아이폰 커서가 사각형으로 움직인다
- 메모 앱에 "hello edgelink"가 입력된다
- 실패하면 `bthid serve`로 아이폰 쪽에서 연결을 시도해본다

- 손쉬운 사용 권한만으로 키 입력을 가로챌 수 있는지 확인한다. 되면 입력 모니터링 권한을 온보딩에서 빼서 권한 요청을 2개로 줄인다
- 아이폰 AssistiveTouch 장치 목록에 Mac이 어떤 이름으로 보이는지 확인하고, 버튼 등록 도우미 문구에 반영한다

- 입력 지연이 평균 20ms, 최대 50ms 안이다 (성능 기준 표의 방법으로 측정)
- 아이폰 조작 중 CPU가 3%, 대기 중 0.5%를 넘지 않는다

**2단계 · 권한과 온보딩** (관문: 새 Mac 계정에서 3분 안에 설정이 끝난다)

- 입력 모니터링 확인·요청 코드 추가 (`CGPreflightListenEventAccess`, `CGRequestListenEventAccess`)
- 블루투스 권한 확인 코드 추가 (`CBManager.authorization`)
- 온보딩 창 8단계를 SwiftUI로 구현, 단계 상태를 UserDefaults에 저장
- 권한 허용 시 1초 안에 다음 단계가 열린다
- 온보딩 도중 앱을 끄고 켜면 멈춘 단계부터 이어진다
- 실행 중 권한을 끄면 1초 안에 Mac으로 돌아오고 경고가 뜬다

**3단계 · 전환** (관문: 100번 넘어가고 돌아와서 실패 0번)

- 오른쪽·왼쪽·위·아래 배치 각각에서 넘어가고 돌아온다
- 모니터 2대 이상에서 맞닿은 모서리에는 아이폰을 놓을 수 없다
- 외장 모니터를 빼면 임시 위치로 바뀌고, 다시 꽂으면 원래대로 돌아온다
- 돌아온 위치가 아이폰 포인터 높이와 화면 높이의 10% 안으로 맞는다 (보정 후)
- Dock 쪽 배치에서 넘어간 뒤 Dock이 닫혀 있다
- 마우스 버튼 8개 디스크립터로 아이폰이 정상 연결된다 (3개일 때와 비교)
- 아이폰 AssistiveTouch 추가 버튼 화면에서 버튼 4~8이 각각 인식된다
- 4가지 제스처 각각을 Mac이 먼저 가져가는지 확인하고 목록으로 남긴다
- 제스처와 대체 단축키로 앱 전환기·홈·알림 센터·제어 센터가 열린다
- 아이패드에서 ⌘H, ⌘Tab 옵션이 동작한다

**4단계 · 안전 장치** (관문: 입력이 엉뚱한 곳에 간 적 0번)

- 아이폰 조작 중 Mac에 비밀번호 창이 뜨면 0.25초 안에 돌아온다
- 블루투스가 끊기면 즉시 Mac으로 돌아오고 눌린 키가 남지 않는다
- ⌃⌥⌘Space는 연결됨·아이폰 조작·보정 중 어디서든 동작한다
- 잠자기 후 깨어나면 2초 안에 다시 연결된다
- 기본 기기가 아닌 아이폰이 연결해 오면 확인 창이 뜨고, 거절하면 아무 입력도 가지 않는다
- 블루투스 쓰기를 일부러 늦춰도 이벤트 탭이 꺼지지 않고, 꺼지면 Mac으로 돌아온다
- 아이폰 조작 중 세 손가락 쓸기를 해도 Mac Spaces가 바뀌지 않는다
- 미디어 키 설정을 켜면 아이폰 조작 중 볼륨 키로 아이폰 볼륨이 바뀐다 (기본은 Mac 볼륨)
- ⌃⌥⌘를 누른 채 넘어갔다 돌아와도 Mac에 수정키가 눌린 채 남지 않는다
- 아이폰 조작 중 앱을 강제 종료해도 커서가 보이고 움직인다
- 아이폰 조작 중 화면 잠금(⌃⌘Q)을 하면 Mac으로 돌아온다
- 앱을 두 번 실행하면 두 번째가 꺼지고 첫 번째 팝오버가 열린다
- Mac 블루투스를 끄면 팝오버에 안내가 뜨고 재연결을 멈춘다
- 다른 Mac에 연결된 아이폰에 연결하면 "다른 기기에 연결돼 있어요"가 뜬다
- 단축키를 ⌃⌥Space로 기록하면 입력 소스 전환과 겹친다는 확인 창이 뜨고, VoiceOver를 켠 상태에서 ⌃⌥만 쓰는 조합을 기록해도 확인 창이 뜬다
- 로그 전체에 키 입력 내용과 클립보드 내용이 한 글자도 없다
- 동작 줄이기를 켜면 유리 효과가 크기 애니메이션 없이 나타난다
- MDM으로 권한을 막은 Mac에서 60초 뒤 관리자 문의 안내가 뜬다

**5단계 · 배포** (관문: 다른 Mac에서 DMG로 설치하고 경고 없이 실행된다)

- 번들 ID를 확정하고 Developer ID로 서명
- `build.sh release`로 공증과 DMG 생성
- 새 Mac에서 설치 → 온보딩 → 전환까지 확인

- GitHub 배포 저장소와 `gh-pages`를 만들고 appcast 주소가 HTTPS로 열리는지 확인
- EdDSA 키를 만들고 공개 키를 Info.plist에 넣음, 개인 키 오프라인 백업
- 이전 버전 앱에서 "지금 확인"으로 새 버전이 설치된다
- appcast의 서명을 일부러 틀리게 바꾸면 업데이트를 거부한다

## 위험 요소와 열린 질문

가장 큰 위험은 macOS가 Mac의 블루투스 HID 장치 흉내를 막는 경우예요. 공식 지원 기능이 아니라서 1단계에서 먼저 확인해야 해요.

| 위험 | 영향 | 가능성 | 대응 |
|---|---|---|---|
| macOS가 PSM 0x11·0x13을 막거나 이미 사용 중 | 연결 자체가 안 됨 | 높음 | `bthid`로 먼저 확인. 안 되면 ESP32-S3 같은 USB 동글로 HID를 대신하는 방식으로 전환 |
| 아이폰이 Mac(컴퓨터 종류)을 HID 장치로 받아주지 않음 | 연결 거부 | 중간 | Mac 쪽에서 먼저 연결하기와 아이폰 쪽에서 연결하기를 둘 다 시험 |
| 허락하지 않은 기기로 키 입력이 감 | 정보 유출 | 낮음 | 보안과 개인정보 › 연결 허용 규칙 |
| 블루투스 지연으로 이벤트 탭이 꺼짐 | 입력이 Mac에 샘 | 중간 | 전송 전용 큐, 탭 꺼지면 즉시 복귀 |
| macOS 업데이트로 동작이 바뀜 | 기존 사용자 기능 중단 | 중간 | 시작할 때 자가 진단, 실패 시 원인과 로그를 보여줌 |
| 아이폰 포인터 가속 때문에 위치 추정이 어긋남 | 돌아오는 위치가 다름 | 높음 | 보정 도우미, 아이폰 끝에 닿으면 값을 제한해서 오차 자동 보정 |
| 시스템 단축키·제스처 일부를 막을 수 없음 | 아이폰 조작 중 Mac 화면이 바뀜 | 중간 | 실제 Mac에서 목록 확인 후 입력 탭에 안내 |
| 회사 보안 정책(MDM, 매체 제어, DLP)과 충돌 | 회사 Mac에서 쓸 수 없음 | 중간 | 보안과 개인정보 › 회사 Mac에서 쓸 때 |
| 비공개 API(백그라운드 커서 숨김) 사용 | App Store 배포 불가 | 확정 | App Store 대신 Developer ID 직접 배포 |
| 보안 입력 감지 0.25초 사이에 키가 Mac에 감 | 비밀번호 칸에 글자 입력 | 낮음 | 감지 주기를 줄일지 1단계 이후 측정 |

**열린 질문**

- 번들 ID와 배포 방식(Developer ID 직접 배포로 확정할지)
- 안드로이드를 정식 지원할지, 참고용으로만 둘지 (⌘ 대신 Ctrl로 바꾸는 설정 필요)
- 아이폰 여러 대를 동시에 연결할지, 한 번에 한 대만 둘지
- 동글 방식으로 바꿔야 하면 하드웨어를 같이 팔지
- 사용 통계를 모을지 (모은다면 온보딩 개인정보 문구 수정 필요)
- (결정됨) 단축키 기본 조합은 ⌃⌥⌘로 정함. VoiceOver 조작키와 입력 소스 전환을 피하기 위해서
- Mac이 먼저 가져가는 제스처가 많으면 제스처 대신 단축키를 기본으로 안내할지
- 사내에서 쓴다면 보안팀 검토를 언제 받을지
